# Unnamed server functions, attributed by the error codes they return

The server refuses an action with a 16-bit code, and
[`error_codes.md`](error_codes.md) maps those to the client's own message names.
A function returning `UIIT_MSG_GUILDERR_*` is guild code whatever Ghidra called
it. This is that join, for the functions still named `FUN_`.

Regenerate with `client/tools/ghidra/label_by_error_code.py`.

## This is an attribution, not a name

"Returns guild errors" says which part of the game a function belongs to. It does
not say what the function does, and nothing here should be promoted to a name
without reading the function. The dump's own call-graph attributions are phrased
the same careful way for the same reason.

## The floor that makes it honest

Error codes start at 1, and `mov eax,0x2` is overwhelmingly "return 2" rather
than "return `PARTYERR_UNKNOWN_ERROR`". Without a floor at `0x100` the join
reports **704** unnamed functions, of which **587 return only codes below
0x100**, and `0x0002` alone is attributed to **381** of them — which is how a
first pass concluded that 329 unnamed functions were party code.

With the floor the same join gives the numbers below, which are a believable
shape for a game server. A collision between a small enum and a small return
value is invisible unless you go looking for it.

| | count | was (narrow scan) |
|---|---|---|
| functions raising a code >= 0x100 | 298 | 157 |
| of those, already named | 94 | 40 |
| still `FUN_` | 204 | 117 |
| attributable to one domain | **143** | 88 |
| mixed domains | 44 | 18 |
| no domain derivable | 17 | 11 |

## The second blind spot, fixed 2026-09-16

The join above used to scan only for `mov ax,0xNNNN` / `mov eax,0xNNNN` — the
shape of `return ERRORCODE`. **That misses every code a function assigns to a
local or another register.** `Mastery_LevelUp` raises `0x3802` and `0x3804` into
a stack slot, which is how a whole family went unseen (see `error_codes.md`).

Widening the pattern to any 16-bit immediate move is only safe **because of the
join**. On its own it matches loop bounds, sizes and masks, finding 1,206
distinct values in `0x100..0xffff` against the narrow pattern's 445 — most of
them not codes at all. What makes it usable is that every match must then be a
code the client already names: **the name table is the validation, not the
pattern.** 208 named codes turn out to be raised only in a form the narrow
pattern could not see.

That is the same lesson as the `0x100` floor above, one level up. The floor stops
a small return value being read as a code; the join stops an arbitrary immediate
being read as one.
