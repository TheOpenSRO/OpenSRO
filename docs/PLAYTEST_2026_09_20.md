## Triage

**One root cause covers 5 and 13.** `HudWindow` set its root to `MOUSE_FILTER_PASS` on the
reasoning that it "must not steal clicks from its own children". That is not what PASS does:
PASS delivers the event to the control *and* keeps propagating it, so it reaches
`World3D._unhandled_input`, which walks the character. STOP is what consumes it, and it does
not steal from children -- Godot hit-tests the deepest control first, so a Button inside the
window still gets its click. The same propagation sends an unconsumed mouse wheel to the
camera zoom, which is 13.

Groups, for the order to work in:

- **input routing** (5, 13) -- one fix.
- **items** (7, 9) and the windows around them (8, 10, 11, 3, 4).
- **rendering** (6, 14, 15, 16) -- alpha/material work, needs the render box and a
  measurement each, not a screenshot.
- **features** (17, 18) -- new work, authored-data driven.
- **combat** (1, 2) -- 2 is the attack-distance item already in `docs/TODO.md`.

## What was found on the items still open

**12 (help window see-through, no top bar).** `ifgameguide.txt`'s `Create` section is
declared `"0,0,0,0"` -- a zero rect -- and carries two frames (`GDR_GUIDE_FRAME_1` on
`interface\inventory\int_window_`, and a second on `interface\messagebox\msgbox_window_`)
plus its own paper and tile art. `HudWindow.build` sizes from the frame rather than the
section, so it builds, but which of the two frames it picks and whether the interior tiles
draw has not been established. This one needs a render to settle and a measurement to
confirm -- not an eyeball.

**18 (name tag).** Done for the name: every other entity carried a plate and the local
player did not. The guild line above it is NOT done and was not invented: the client is
never told its own guild. It goes in when the server sends one.

**6, 14, 15, 16 (see-through clothes, hair as a solid block, gold on a black background,
feet visible while idling).** All four are alpha/material questions and all four are the
kind of thing this project has been wrong about from screenshots before. Each needs the
render box and a measurement -- the texture's own alpha channel, the material's transparency
mode, the draw order -- rather than a look. `docs/WORLD_ISSUES.md` has the standing rule.

**8, 11 (inventory a mess; nothing under character control).** UI layout work against the
authored resinfo files, in `hud_panels.gd`. Item 9's investigation cleared the bag's data
path: the grid is wired to `inventory_list_result`, a pick-up re-reads the bag, and
`_fill_inventory_grid` skips any slot index at or past the lattice's cell count -- which is
worth checking against `inventory.SlotsPerCharacter` (50) when 8 is picked up.

**17 (graphics options).** New work: the original's options window has a graphics section
and ours has none.
