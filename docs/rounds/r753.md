# Round 753: the static-from-lambda census, and a lint that keeps it out

Round 752 found that Godot 4.2.2 runs some lambdas with a null self. A lambda made in an instance
method, whose body names only a static function of its own class, fails on a bare call to that
static: `SCRIPT ERROR: Invalid call. Nonexistent function '_spin_step' in base 'Nil'`. That one
line (`UiBuilder._build_spin`) left the party-match and warehouse page arrows dead, and no test
caught it. This round looks for every other case in the client and adds a suite that fails on
the pattern.

Based on `b7b89bed` (dev, v0.1.511). Labels: READ, MEASURED (run here), OURS, OPEN.

## The result

**No other broken call site exists.** The client has no lambda left that calls a static by its
bare name with a null self. Round 752's `_build_spin` arrow, already fixed, was the only one. So
no call needed qualifying this round, and no feature other than the two page spins was ever
broken this way.

The census was MEASURED by two independent scanners, and both cover every `.gd` under
`client/scripts`, tests included. One is a Python prototype in the scratchpad; it gives the
counts below. The other is the new lint suite, run on the box. Both find 0:

- **355 lambdas** in all: 299 made in an instance context, 56 in a static one.
- **19 lambdas** call a static of their own class (or of a script parent) by the bare name:
  - **17 are made in a static func.** The probe shows these work. They are in `video_options`
    (2), `efp_effect` (2), `audio_bank` (2), `npc_talk_view` (4), `ui_builder` (2),
    `mapm_terrain_builder`, `charselect_math`, `title_cell_plan` (2) and `ground_probe`.
    Round 752 counted 7 of them; it scanned only one-line lambdas.
  - **2 are made in an instance method and also use the instance**, so they capture self and
    work:
    - `World3D.gd:21181`, the counter-blow `_after(...)` lambda. It calls `_fx_owner_key` and
      also `_audio_mark_hit`, `_play_player_struck` and other instance methods. World3D has no
      `class_name`, so it could not be qualified by name anyway.
    - `ui/hud/hud_panels.gd:5973`, the `equipment_result` handler. It calls `_first_field` and
      `_durability_by_slot`, and also writes `_equipped_items` and calls `cancel_held_icon`.
- **0 are made in an instance context with no self.** This counts lambdas in class-level `var`
  initialisers and inner classes too.
- `client/tools` was also scanned by the prototype, and none were found there. No scene holds a
  built-in script.

## What makes a lambda lose its self (MEASURED, bare 4.2.2 project on the box)

Three probe scripts were run under `/var/tmp/lambda/probe` with
`Godot_v4.2.2-stable_linux.x86_64 --headless`. Each lambda calls a static that records a tag:

| lambda (made in an instance method unless stated) | result |
|---|---|
| bare static call | NOT reached (`... in base 'Nil'`) |
| qualified `ProbeHolder.bump()` | reached |
| bare call to a static of the **parent** script class | NOT reached |
| the body also reads a `static var` | NOT reached |
| the body also reads a `const` | NOT reached |
| the body also reads a captured local | NOT reached |
| the body also builds `[1].map(func(v): return v)` (no member) | NOT reached |
| the body also writes a lua-style key, `{sig = 1}`, that names a signal | NOT reached |
| the body also calls an instance func, reads an instance var, or uses `self` | reached |
| the body also calls a native method (`get_reference_count()`, `get_tree()`) | reached |
| the body also reads a native property (`name`) | reached |
| the body also emits a signal of the class (`sig.emit()`) | reached |
| the body also uses `$Kid` or `%Kid` | reached |
| a lambda nested inside it uses an instance func | reached (self is marked outwards) |
| the outer lambda uses a member, the **nested** one calls the static | NOT reached |
| the static only referenced: `var c := bump; c.call()`, `bump.call_deferred()` | reached |
| `bump.bind(...)` outside any lambda | reached |
| a class-level instance `var` initialiser, `var cb := func(): bump()` | NOT reached |
| an inner class's method calling its own static | NOT reached |
| made in a static func | reached |
| made in a `static var` initialiser | reached |
| an inner class's lambda calling the **outer** class's static by bare name | parse error (`Function "bump()" not found in base self`) |

So only a *call* breaks, never a reference. A lambda captures self only when it names something
of the instance: `self`, an instance variable, function or signal, a native member, `$` or `%`.
The last row means an outer class's static never reaches run time, because the compiler stops it.

## The lint: `client/scripts/ui/static_lambda_lint_test.gd`

It is modelled on `const_array_lint_test.gd` and is text-based: it loads no script it checks. For
every `.gd` under `res://scripts`:

1. **Strings and comments are blanked** to spaces, keeping offsets and line numbers. A pattern in
   a string or a comment is not code.
2. **Classes are parsed.** For the top-level class and each inner class it records:
   - its static funcs;
   - its instance members (funcs, vars, signals);
   - its static names (static vars, consts, enums, inner classes).

   Each line gets a context: the class it is in, and whether it is static or instance. That is a
   `func` or a `static func` body, or a class-level `var` or `static var` initialiser. Parents
   resolve through `class_name`s, inner names and `extends "res://..."` paths. A parent named by
   path is read from the raw line, since its string is blanked.
3. **Lambdas are found and their extents taken.** A one-line body runs to the `,` or the
   unbalanced bracket that ends it. A multi-line body runs to its indentation.
4. **A finding** is a bare call (not after `.`) to a static of the lambda's class or its script
   parents, from a lambda made in an instance context. The lambda, with the lambdas nested in it,
   must also name nothing of the instance:
   - not `self`, `super`, `$` or `%Name`;
   - no instance member of the script chain;
   - no method, property or signal of the native base. These come from `ClassDB`, inherited ones
     included, with group and category entries dropped.

   A call inside a nested lambda is charged to the nested lambda.
5. **Locals shadow members.** The enclosing function's parameters and vars, the lambda's own and
   its nested lambdas' are all treated as locals. A lua-style dict key and a named lambda's name
   do not count. Taking too many locals only flags more.

**The self-check** (`_test_detector`) runs the detector on a two-file snippet: a parent
`LintParent extends Control` and a child `LintSnippet extends "res://lint_parent.gd"`. It
must flag exactly lines `[7, 12, 16, 23, 25, 27, 34, 40, 45]`:

- 7: an instance `var` initialiser;
- 12: round 752's arrow, `func() -> void: _spin_step(ctrl, step)`, with the callee named;
- 16: a body that reads only a static var and a const;
- 23: a parent's static;
- 25: a lua-style key;
- 27: a `"%d" %v` format, which is not a unique node;
- 34: a nested lambda under a self-using one;
- 40: a parameter `visible` shadowing the Control property;
- 45: an inner class's own static.

It must flag none of the forms that work:

- a qualified call;
- a member, or a signal emit;
- a native method (`get_index()`) or a native property (`visible`);
- `self`, `$Kid`, `%Kid`, or a self-using nested lambda;
- a lambda made in a static var initialiser or a static func;
- a reference to the static that is not a call;
- the pattern inside a string or a comment.

**NEGATIVE, MEASURED.** The box's copy of `ui_builder.gd` was given round 752's bare
`_spin_step` back. The suite then failed:

```
  res://scripts/ui/ui_builder.gd:1287 calls static _spin_step from a lambda with no self: btn.pressed.connect(func() -> void: _spin_step(ctrl, step))
FAIL no lambda made in an instance context calls a static by its bare name with no self, in 546 scripts (1 found, 918 ms; ...)
```

On the real tree it reads "546 scripts (0 found, 908 ms)", ALL PASS.

**Limits (stated).** The lint reads text, and it does not run Godot's analyser:

- It does not follow a static called through a preloaded const alias of the same script
  (`const Me = preload(...)`, then `Me._f()`). That form is qualified, and works.
- A member name used only as a lua-style key or as a named lambda's name is ignored as the probe
  says. A member name in another position that is not a reference would hide a finding. None
  was seen.
