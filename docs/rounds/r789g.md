## 2. Measured before deciding (the five retail archives)

A census over all five (`WalkAll`; a throwaway tool, not committed):

- **Non-ASCII names exist**: CP949 Korean bytes in 19 names (Data 7, Media 3, Music 7, Particles
  2, Map 0), e.g. Media's three `fonts\*.ttf`. So the name encoding had to be a rule: a pk2 name's
  bytes are Latin-1 code points (what the client already does), written into a zip as UTF-8 with
  the UTF-8 flag (OURS).
- **No duplicates**: 0 shadowed entries under the client's case folding, in all five.
- **The base archives are not one namespace**: 40 paths are in two archives, **5 differ** (Data's
  and Map's `object.ifo`, `objectstring.ifo`, `regioninfo.txt`, `mapinfo.mfo`; Data's and Media's
  `resinfo\itemtypenumber.txt`). A single merged namespace would hand a reader the wrong
  `object.ifo`. Hence rule 3 (OURS): a lookup names its volume (the client's `find_file` always
  does); packs overlay every volume; an unscoped lookup cascades the bases by name.
- Largest entry 21,352,219 bytes (Data `navmesh\ainavdata_32773.dat`): the 256 MiB entry cap is
  twelve times that (OURS).
- Deflate ratios by extension (level 6, up to 300 files each): `.ogg` 99.4%, `.rar` 98.6%, `.png`
  90.3% -> stored; `.wav` 75-81%, `.ddj` 25-80% -> deflated. The TODO assumed `.ddj` is "already
  compressed"; it is not, so the converter deflates it (OURS, from the measurement; `-store .ddj`
  for an operator who prefers stored textures, +0.63 GB on Data).
- Largest per-entry ratio in retail: **974.6:1** (Media `script\image\qno_script_background_white.ddj`).
  My first ratio cap (1000:1) was 2.6% from refusing a retail file. The cap became 1100:1, above
  deflate's ~1032:1 ceiling, per entry and per pack (a pack's total against its file size, which is
  what catches overlapping-entry bombs). OURS; the reasoning is asset_packs.md rule 6.

## 3. What was built (all OURS)

- **`internal/pk2`** (find.go): `Find`, `ReadPath`, `Children`, `Walk`, `WalkAll`
  (shadowed entries flagged), `OpenEntry`, `Fold`, `SplitPath`; a per-folder name index cached per
  archive (first entry of a folded name wins, as the client). Empty segments are skipped (the
  client's split fails on them instead; harmless difference, noted in the code). `pk2test`
  writes synthetic archives (nested folders, chained blocks, duplicate names) for every test.
- **The ten walkers** (`auditcharacters`, `audittextures`, `o2sectors`, `heightat`, `waterat`,
  `whatishere`, `scanlandmarks`, `findregionassets`, `mapobjcensus`, and `pk2list`'s
  `extractFile`) now call `ReadPath`/`Find` (326 lines deleted, 37 added). `efpcensus` and
  `internal/efp/census_test.go` keep their whole-tree walks (they are not lookups).
- **`internal/assetfs`**: the layered file system (rules 1-6), `In(volume)`, `Which`/`WhichAll`,
  merged `ReadDir`/`Walk`, override logging, strict mode for exporters, `custom/` (symlinks
  refused), symlinked archives allowed in the folder; `PackWriter`/`WritePack`/`VerifyPack`;
  `Inputs`/`InputFlags`.
- **`cmd/pk2topk3`**: converter (+ `-measure`). **`cmd/pk3pack`**: pack builder.
- **`cmd/pk2list`**: `-pk2` takes a `.pk3`; `-archives` with `-layers`, `-which`, `-overrides`,
  `-volume`, `-source`, `-custom`, `-l`. The plain listing keeps its format (size, path), so
  deploy/README.md's `awk '{print $2}'` pipelines still work; a non-ASCII name now prints as UTF-8
  and the raw-byte spelling still resolves.
- **`export-refdata` / `export-leveldata`**: `-archives` (+ `-source`, `-custom`, `-no-custom`,
  `-volume`, `-textdata`); `@<index>` expands an index file's parts in order (the README's `order`
  function), in both modes. Inputs resolve in the named volume (Media), then every layer (so
  `navmesh\objectstring.ifo` finds Data's), then disk (the server's `.sct` files).
