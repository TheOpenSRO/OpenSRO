# Round 789, lane U: the server names the packs a client needs

Round 789 is "asset packs (.pk3) and working avatars" (the user, 2026-10-16). The plan in
docs/TODO.md, "Asset packs: `.pk3` beside `.pk2`" (decided 2026-10-01), ends with: "The server names
the packs a client needs, with their hashes (idTech's 'pure server'), and the auto-updater fetches
them. Then every player sees the same content, and a modified local pack cannot change what the
server assumes." Lanes G and K built the rules, the Go readers and the client's layered archive set,
and left `AssetArchives.reopen()` / `current_generation()` for this lane. Lane U (this note) built
the rest: the server's `-client-packs`, the wire, the client's download, verification and layering,
purity. Branch `feat/pk3avatar789-u`.

Labels: **READ** (our own code), **MEASURED** (the render box 192.168.10.78, Godot 4.7.2,
`RENDER_DIR=/opt/opensro-client-789u`, GDScript readers -- no native library in that copy),
**OURS**, **OPEN**. Retail has only `.pk2` and no such exchange: everything here is OURS; nothing
was read from a binary. The spec is docs/protocol/asset_packs.md, "Server packs"; the operator's

## 1. What was there (READ)

- `AssetArchives.reopen()` (lane K) rebuilds the shared set from the mode and the folders; caches
  keyed by `Pk2Reader.cache_key()` (item/NPC tables, UI fonts) and AudioBank (by set generation)
  parse again. Its pack list came only from discovery in one folder.
- Two before-login questions already exist on a short connection of the client's own:
  the theme (0x0005 -> 0x0006, `ThemeQuery`) and the server list's status (0x0007 -> 0x0008), both
  `GatewayQuery`s. The server's handler chain drops an opcode no handler claims (so an old server
  ignores a new question) and the client warns once per unknown opcode (so an old client is not
  hurt by a new message). 0x0009 and 0x000A were free on every round-789 branch (grepped).
- The login screen connects on Connect (`Login._connect_and_send`); a QA world boot signs in
  through `QaSignIn.run` from inside `World3D._ready`, after World3D has opened its archives and
  started the item/character table preloads.
- The client updater (`client/scripts/update/`) updates the client itself from GitHub releases
  with `HTTPRequest`; nothing there fetches assets.

## 2. Built (OURS)

**Server** (`server/internal/clientpacks`, `server/internal/session/clientpacks.go`,
`server/cmd/server/clientpacks.go`, four flags in `main.go`):
- `-client-packs <dir>`: every `.pk3`/`.zip` in the folder is opened through
  `assetfs.OpenArchive` with the readers' limits; a pack with any refused entry is refused whole;
  every entry is read back (CRC and size); the file is hashed (SHA-256); size and modified time are
  kept; the list is sorted by rule 2 (`assetfs.SortCascade`, exported for this) and logged. Any
  other file, a base name, an unsafe name, two names differing in case, more than 32 packs, 4 GiB
  a pack or 16 GiB together stops the server.
- `-client-packs-url <base>` (`<base>/<name>`), `-client-packs-listen` (default `:15780` when no
  URL; bound before the gateway, its port in the manifest), `-client-packs-local-extras`.
- The listener (`clientpacks.Handler`): GET/HEAD `/packs/<name>` for listed names only, ranges and
  `If-Range` (ETag = the hash), 503 for a file changed since startup, 16 at once, 2 and 60 a minute
  per address, a stalled writer cut after 60 s, no ReadTimeout (net/http's background read would
  cancel a long download).
- `ClientPacksHandler`: answers 0x0009 with 0x000A once per connection, ends an unauthenticated
  connection after it (the theme's rule). A server without `-client-packs` answers too ("no packs
  named"), so a new client does not wait on it.

**The wire**: asset_packs.md "The manifest"; golden vectors `client/scripts/net/testdata/
client_packs_golden.json` (5 good, 25 bad), spelled field by field from the layout (a throwaway
helper wrote the hex of each hand-chosen field; neither implementation was used), held by
`TestManifestGolden` and `pack_manifest_test.gd`.

**Client** (`client/scripts/update/`: `pack_manifest.gd`, `pack_query.gd`, `pack_store.gd`,
`pack_download.gd`, `pack_sync.gd`, `server_packs.gd`; small hooks in `asset_archives.gd`,
`Login.gd`, `qa_sign_in.gd`, `World3D.gd`):
- **When**: on Connect, before the connection that carries the login (Login), and first thing in
  a QA world boot (World3D -> `QaSignIn.sync_packs`) so the world's tables are read after the
  switch. Not at boot (the server is chosen on the login screen); not on the game connection (a
  download may take minutes; the screen shows its progress first).
- **Where**: `<pack folder>/servers/<host>_<port>/`; partials `<name>.<16 hex of the hash>.partial`;
  hash cache `packs.json` (size, modified time, SHA-256); `sweep` removes what the list no longer
  names, nothing else.
- **Download**: HTTPClient polled a frame at a time; resume with Range/If-Range after hashing the
  partial; 200 restarts; the manifest's size is a hard cap; 3 resumes a source, then the next
  source (URL, then the listener); 5 redirects; 30 s stall; wrong hash -> partial removed, one fresh
  retry when any bytes came from an earlier attempt; free space checked first; rename into place.
  https from anywhere, plain http only from the gateway's host.
- **Purity**: `ServerPacks` holds the selection; `AssetArchives._config_opts` asks
  `ServerPacks.layer_opts`: the server's packs exactly (local packs and `custom/` set aside and
  logged), or with LOCAL_EXTRAS the local packs below and `custom/` on top. Server packs are read
  in every source mode. A server with no list, an old server, a legacy server: the player's own set.
- **The switch**: `ServerPacks.apply` reopens only when the layers change, then drops the statics
  that do not key on the set (`lobby_text`, NameFilter, QuestTables, MagicOptionTable,
  ItemGlowTables, DamageText art; AudioBank cleared). The login screen takes the new set's Media for
  what it still opens and the content id it sends.
- **The player sees**: the message line (`Checking the server's packs...`, `Downloading
  z_akatsuki.pk3: 0.3 MB of 0.6 MB (50%)`, plain errors); the log has a `PACKS:` line per step.

## 5. How the coordinator runs the end-to-end test with the Akatsuki pack

On the box, as root (the server) and as ghidra (the client), with any branch carrying lane U:
1. Build `opensro-server` and `pk3pack` (`CGO_ENABLED=0 GOOS=linux go build`), put them in
   `/var/tmp/u789/bin/`; or reuse lane U's.
2. `bash /var/tmp/u789/setup.sh` -- builds `u789_test.pk3`, copies `/var/tmp/x789/z_akatsuki.pk3`
   to `/var/tmp/u789/serverpacks/`, starts the server on 127.0.0.1:15897 with
   `-client-packs /var/tmp/u789/serverpacks -client-packs-listen 127.0.0.1:15898` and the item rows
   of `/var/tmp/x789/items_with_akatsuki.csv` (the merged branch's server: rebuild first).
3. Sync the merged client to a copy (`RENDER_DIR=... client/tools/remote_godot.sh sync`), point
   `CLIENT_DIR` in `/var/tmp/u789/run.sh` at it, `rm -rf /var/tmp/u789/clientpacks/servers`, then
   `su - ghidra -c "bash /var/tmp/u789/run.sh run1 400"` (the first login: downloads) and
   `... run2 500` (through Login: downloads nothing). Read `/var/tmp/u789/run1/godot.log` and
   `run2/godot.log` for `PACKS:` and `QA WHICH`, and `/var/tmp/u789/logs/server.log` for `client
   pack served`. With lane AC merged, add `--shots`/`OPENSRO_QA_EQUIP` to run1 to look at the robe:
   the archive side needs nothing more.
4. Stop the server: `pkill -f "[/]var/tmp/u789/bin/opensro-server"` (the bracket keeps pkill off
   its own ssh command line, AGENTS.md's trap; qa_shot's reap of `opensro-server -in-memory` does
   not match it either, because `-addr` comes first). `/var/tmp/u789/clientpacks/zz_local.pk3` and
   `/var/tmp/u789/custom/` are run3's purity fixtures: every run shows them set aside.

## 6. OPEN

- A bandwidth limit on the listener (only concurrency and request-rate caps are built).
- Two servers that ship the same pack each download it (no shared content-addressed store).
- After a switch between two servers with different packs in one run, the effect and particle
  caches keyed by path (`EfpEffect`, `AmbientParticles`) keep what they read from the first.
- A pack a player edits and gives its old size and modified time back passes the hash cache.
- The title screen is built from the player's own set (it is drawn before a server is chosen); a
  server's pack that changes title art shows from character select on.
- Not tested: a real https CDN or GitHub release download (no outside network on the box); the
  redirect and resume logic are tested against the in-process server and the Go listener.
