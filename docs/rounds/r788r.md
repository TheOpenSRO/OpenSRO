# Round 788, lane R: the original client logs in to OpenSRO's server

**Asked:** make OpenSRO's Go server accept the ORIGINAL retail client (sro_client.exe, vSRO 1.188,
content id 22, version 1000) through login to the character list -- the user's "Retail login, both
ways", this lane being the "original client -> our server" half. The world is out of scope: Start
refused cleanly with the most honest retail code. Then the real proof: run the original client
against it.

**Result:** done and MEASURED. The original client, under Wine on the render box, handshook with
OpenSRO's retail gateway, listed its shard, logged in, moved to OpenSRO's retail agent, presented
its token, and showed its character list -- the account's character standing in its armour on the
select screen. Start shows the client's "GameServer is currently offline" text and the screen
stays usable.

Labels: **READ** (the binaries, addresses given; sro_client's unless named), **MEASURED** (the render
box, 2026-10-15), **INFERRED**, **OURS**, **OPEN**. Branch `feat/acct788-r` from `feat/acct788`.

## 2. READ this round (two research agents, then checked against the live client)

GatewayServer / AgentServer (full Ghidra decompiles now in `/var/tmp/r788r/dec_*` on the box):

- Both send hello flags 0x0E (option bytes gateway 3, agent 2; writer 0x46eab0). A server sends no
  0x2001 first; it answers the client's with `[name, 0]` plain (0x43f5a0 / 0x42c180), then massive
  0x2005 and 0x6005 (0x43f854..0x43fa45 / 0x42c447..).
- 0xA100 (0x4051a0): `[1]` equal version; `[2,1]` unknown module, version 0 or higher; `[2,2,...]`
  a patch (layout in gateway.md); `[2,3]` older with no patch server; `[2,4]` not in service;
  `[2,5]` a per-module minimum. The content id is only logged (0x405508). No disconnect.
- 0xA104 (0x406380 / 0x4013e0): massive `u8 count, {string, string, 16 bytes}`. 0xA106 (0x405740):
  plain `u8 count, {u8, u32 IPv4}`.
- 0xA102 success is encrypted (0x405e7d); the 0x6102 handler's refusals plain. 0xA103 encrypted on
  every path (0x40226a..0x40312f); every 0x6103 refusal disconnects (0x402608); content id
  mismatch: no reply, disconnect (0x402225).
- Tokens: AgentServer's own sequential pool of 500 (0x409a40 / 0x40a510), expiring past 10000 ms
  (0x409fc9), swept every 3 s (0x4017cc).
- Keep-alive 0x2002 discarded (0x4405c0 / 0x42d2a0); sessions swept every 10 s, closed past 60 s
  idle (default 0xea60, 0x43eda0; no override found -- the 60 s INFERRED).
- The agent drops lobby messages from a session with no user (0x4315d0); relays the shard's
  replies plain (0x403348); never builds 0xB001 / 0xB007 itself.

sro_client:

- The dispatch table (64K entries, `CClientProcess::vslot_002` 0x4ce560) -- settles round 681's
  INFERRED handler mapping (gateway.md).
- 0xA102 reader (0x4cf500) checks only the result byte; no IBUV state. 0x6103 is sent from inside
  the agent's 0x2001 handler (0x4ceb86).
- After 0xA103 [1]: the title switches to `CPSCharacterSelect` (0x865b10, 0x865210), whose OnCreate
  sends 0x7007 [2] plain (0x8560e0; only 0x704C goes encrypted, 0x841590). Nothing else needed.
- 0xB001 failure codes and texts (0x861a40, index 0x861b84); the select screen locks its UI on Start
  (0x862410(1)) and only the 0xB007 path unlocks (0x85fffa).
- Keep-alive: 0x2002, plain, after 5 s without a send (timer 1666 ms, 0x4cf990), on both connections.
- Command line: the text after the first '/' is `%d %d %d` (content id, division, gateway index,
  0x846b46); the gateway host and port come from Media.pk2's DIVISIONINFO.TXT / GATEPORT.TXT
  (0x846cc9.., 0x84712e..). The client binds TCP 15779 as a single-instance guard (0xb3eb30).
- Corrections to the research agents found live: the client DOES send 0x6106 (MEASURED; the agent
  had INFERRED never), so the mode word gating it and the A101 farm byte is 1 at run time.
- Found while running it: the net init fails with "connection failed (17)" when a directory string
  taken from the command line is empty (0x4c9190, `lstrlenA`); starting it with the exe's full
  path first, as the launcher does, fixes it.

## 3. OURS (each in code and gateway.md)

- One farm (id 1) and one shard; `-retail-shard-id` 1, `-retail-shard-name` OpenSRO.
- Content id 22 / version 1000 defaults (MEASURED values of the box's archive). Version: above or 0
  `[2,1]`, below `[2,3]`; never `[2,2]` (no patch server).
- The list and the login only after an accepted 0x6100 (retail's dispatcher rule OPEN).
- 0x2005 / 0x6005 not sent (no client handler; a field of INFERRED meaning).
- IBUV skipped (the client does not require it, READ; the image format unknown).
- The gateway decides the login with no session; the agent admits the session (`AdmitSession`).
- Tokens random u32, one use, 10 s (retail's lifetime); credentials compared ID-without-case,
  password exactly (constant time).
- Start refused with 0x40F `UIO_SMERR_CANT_ACCESS_PARENT_SERVER` (the only select-screen text that
  says the game server is not there), **followed by the list unasked** so the screen unlocks.
- The retail gateway does not close the connection after a successful 0xA102 (the client does).
- No idle limit on the retail listeners.
- The packet log: every message both ways with its bytes, at Info (the keep-alive and the 5 s
  list refresh at Debug); 0x6102 / 0x6103 bodies withheld.
