## 2. READ this round

`Stat_ApplyTaggedModifier` (`s:0x498690`): the avatar tags' params and ParamKeeper slots were not in
`combat.ParamFor` (only `hpa`, `hra`, `hprg`, `mprg`, `mpna`, `drua`, `strv`, `intv`). Walked from the
disassembly on the RE box (`/var/tmp/srgs.asm`, each `cmp eax,TAG` / `je` to the leaf's `mov edi,N`
and the slot it pushes before `ParamKeeper_SetParam 0x4b3510`):

- `stra` -> p1 slot 0 (0x499123, adding the entry the item already has, read by 0x4b3830), `inta` ->
  p2 slot 0 (0x498dd0), `mpa` -> p4 slot 0 (0x498a12), `era` -> p9 **slot 1** (0x49890f), `hra` -> p11
  slot 1 (0x498a8e), `hprg`/`mprg` -> p25/p26 slot 1, `hpna` -> p52 slot 1 (0x498cec), `mpna` -> p53
  slot 1, `drua` -> p128..131 slot 0, `dara` -> p174..177 **slot 2 with the value negated** (`fchs` at
  0x498b2e), `luca`/`luck` -> p173 slot 0 (0x498e8f), `mdia` -> p188 slot 0 (0x498e42), `umdu` -> p259
  slot 0 (0x499192).
- `brna` and `bri` branch on the item's `+0x190` before their leaves; not followed (OPEN).

The slot meaning (0 flat, 1 percent, 2 multiplier) is round 785's EvaluateParam reading
(`buff/stats.go`).

## 3. OURS choices

1. **The store**: the bag's inventory store on its own table (`avatar_inventory_slots`), not a new
   store type; capacity 5.
2. **The devil's spirit's expiry** is kept in the instance's `Durability`, where retail keeps it (the
   Data word); `0` and `-1` both mean "never awakened".
3. **A malformed 0x23/0x24 body** (not exactly its two bytes) is answered `3`.
4. **INTERACTMODE**: an established trade is retail's mode 2 (0x1834); a pending invitation does not
   block. No stall (4), no mode 7.
5. **The list request** 0x0044 carries the bag list's character name, or nothing for the session's
   character; a request naming no character of the session's is not answered.
6. **The spawn block** leaves out an id the item table does not know (the client would read it
   without its plus byte).
7. **The lobby u8** is the OptLevel (INFERRED; what the ShardManager writes is OPEN).
8. **The integrity check at the world entry moves a failing item to the bag** (and refuses the entry
   only when the bag is full), where retail refuses the login. Every failing state comes from outside
   the game (an item table change, a database edit, a bug); retail's answer locks the character out
   until an operator repairs the database.
9. **The devil's spirit's own blue options count while it is awake** although the opt-level ability
   step's tables are not loaded (the missing tables are not read as the step failing).
10. **The expiry while worn** runs on a timer at the expiry (armed at the move, the list request and
    the world entry), where retail checks on every storage operation.
11. **The awakening** is the devil's spirit's use from the bag (which use reaches vslot 325 in retail
    is OPEN); the item is not spent. **The Nasrun extension's target** rides OpUseItem's option byte
    (the wire slot, bag + 13).
12. **The grant needs no talk state**, as retail (READ: none checked); the grant is free. A grant whose
    name is shorter than its length is answered 0xa (retail clamps the length and does not find the
    clamped name).
13. **Op 7** is answered at once rather than after the operation's wait.
14. **The Test Items NPC**: three lines (men's and women's hat / dress / attachment from the item mall
    family, 30 each, and all devil's spirits; flags by gender and the extensions); avatars and devil's
    spirits sold +0 with no options, a spirit not awakened. The archive's 1,381 avatar ids do not fit
    a store with 4 tabs a line, 30 goods a tab and no page spin.
15. **GM `/avatar`** and `/avatar spirit` (a test tool).
16. **The regen tick** now evaluates params 25/26 with their other entries (an avatar's `hprg`/`mprg`,
    and a buff's percent writes, which it ignored before). This follows the READ formula
    (`EvaluateParam(25)`), and changes regeneration for any buff that writes them.
