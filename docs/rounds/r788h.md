## READ this round (beyond the research note)

- **The hover help -- a correction.** The research note's "no tooltips on the bar (INFERRED)" is
  wrong. `CIFExtQuickSlotSlot::vslot_019` (`0x65fb90`) forwards every message to the target slot
  and, for 0x4009, calls `0x776c00(GetRect(), 0)`. 0x4009 is the hover: the target's
  `CIFSlotWithHelp::vslot_019` (`0x667820`) calls its vslot 48 (the help, `0x686db0`) on 0x4009 and
  hides interface +0x730 / +0x734 on 0x400a. `0x798db0` returns interface +0x730, and `0x776c00`
  re-places that window beside the given rect: x = right + 8 (left - width - 8 when right + 0x14 +
  width passes the screen width), y = top + 8, kept 0xf above the bottom. So a skill on the bar
  shows its tooltip, beside the bar's slot. Built: the lent node keeps its bubble tip
  (`World3D._wire_quickslot_tip` now covers every slot index).
- **apply() in the asm** (`0x65f390`): the alpha goes to WND (10) and 11..14 always, and while open
  to END (0x14), then for the one-line types slots 100+i and boards 30+i (i < 10), for the two-line
  types slots 100+i (i < 10) and boards 30+i (i < 5); then `0xb9daf0(!+0x370)` on 100..109 and
  `0xb8f540(!+0x371)` on 10. Matches the note.
- **The option window's placement** (`0x65eb10`, asm `0x65ebba..0x65ec78`): the GetRect at
  `[esp+0x14]` is x, y, w, h of the bar; vertical: `x < screen_w >> 1` -> SetPos(x + w, y), else
  `0xb8f480` (the window's size) -> SetPos(x - opt_w, y); horizontal on y and h likewise. Matches
  the note; no clamp, so at the default place a horizontal bar opens it partly off a 1280-wide
  screen (MEASURED, run 1), as retail would.
- **The collapse** (`0x65ecd0`): types 0/1 swap to `qsl_hopen_button` (collapsed, string at the
  call with 0x29) / `qsl_hclose_button` (open), types 2/3 `qsl_vopen_button` / `qsl_vclose_button`;
  then the slots and boards are shown or hidden, then END.

## OURS, every choice

- **Where the slots of the extra bars live.** The coordinator's brief assumed OpenSRO saves quick
  slots server-side; it does not. Since round 639 the bar lives on the client
  (`HotbarStore`, `user://quickslots.cfg`, at the user's request), and the server stores only
  0x7158 type 2 (the auto potion, `session/autopotion.go`: "The quick-slot types 0 and 1 are not
  stored"). Slots 41..50 already survived a relog (the store took 0..50; the live run below confirms
  it). So the extra bars' slots go where the others go: `HotbarStore` now takes 0..250
  (`HudUnderbar.SLOT_COUNT`). **No server, protocol or Go change** -- and no Go test for an
  extended save, because there is no server save to extend. An old client skips entries past 50
  (its own range check) and drops them at its next save; a new client reads an old file unchanged.
- **Slot numbering:** bar b, page p, key k = `51 + ((b-1)*5 + (p-1))*10 + k`; a fixed stride per
  bar so raising either count moves nothing.
- **Page labels** `F5`, `F6`, ... (after the bottom bar's F1..F4; the reference's first page reads
  F5). The arrows step and wrap. No key turns them (F5..F8 stay unbound, as in retail).
- **Default counts:** 1 extra bar, 4 pages; limits 0..4 bars, 1..5 pages.
- **The footer geometry**, MEASURED from the screenshots (BwsSwhY.png 1.91x by 2.0x, LW9chOy.png
  2.0x): 23 px past the slot area (bar 2 is 232 / 232.5 long against retail's 209 / 213); the
  arrows' art 12x20 (11.6-12 at 1x), flush with the slot area's end, 2-2.6 px in from each side
  (taken as 2 both sides); the label centred between the arrows (x 212.5..224.5 measured, 209..229
  built). The one-line types' footers follow the same rule, not measured. The horizontal arrows are
  the left/right art turned a quarter clockwise (`UiBuilder.rotated_cw`); there is no up/down art.
  The backing is the header art's grip lines 2..12 repeated and its edge lines 0..1 turned outward
  (MEASURED: all four `qsl_*_windo` have that structure); on a horizontal bar the END cap is not
  built. The label is white at full alpha (the reference shows a white F5 on a transparent bar);
  band and arrows take the alpha with the boards.
- **Keys:** Alt+1..0 fires the first extra bar's page slot. Space and Ctrl are retail's, Shift is
  retail's plain digit (`0x780610` tests no Shift), Alt+digit's retail meaning is unread
  (no `WM_SYSKEYDOWN` in the message map); before this round OpenSRO treated Alt+digit as the plain
  digit (keymap_test updated). Bars 2.. have no keys.
- **The count row:** in the extra bars' option window only (retail's stays as authored), a
  30-px band at y 175 ("Bars" / "Pages", each a value between `qsl_left_arrow` / `qsl_right_arrow`),
  the button band moved down; takes effect on Apply / Confirm. 0 extra bars only through
  `settings.cfg`.
- **Persistence:** `[ext_quick_slot]` in `settings.cfg` -- `options_<n>` (six 0/1 ints, retail's
  order), `position_<n>`, `extra_bars`, `pages`; written on change and at the end of a drag. A
  damaged entry reads as none (retail: a bad version leaves the ctor's open-only state).
- **Default places:** extra bar n at retail's default moved left by n x (header width + 4).
- **Clicks between the slots** (on a board) do not reach the world (boards consume them); retail's
  boards are CIFStatics, whose hit-testing was not read.
- **Option window and Escape:** not read; Escape leaves it open.
