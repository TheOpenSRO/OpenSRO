# Round 788, lane C: the client's login, as the original client does it

Asked (round 788, "Account & login to 100%", the user's "Retail login, both ways"): the CLIENT side
of logging in, exactly as sro_client.exe behaves, to OpenSRO's own server and to a retail
("legacy") server -- 0x6102 / 0xA102, the image code (IBUV), the agent's 0x6103 / 0xA103 and the
character list; the title's messages built as the original builds them; a connection the server
closes at the front end shown as the original shows it. Entering the world on a legacy server is out
of scope (its world protocol is not the original one).

Labels: **READ** (sro_client.exe's decompile and `/var/tmp/sro_client.asm`; GatewayServer
`/var/tmp/retailgw681/gw.asm`; AgentServer `/var/tmp/acct788/agent.asm`; ImageTrans.dll from the
operator package), **MEASURED**, **INFERRED**, **OURS**, **OPEN**. Branch `feat/acct788-c` from
`feat/acct788` (`107c4a99`).

## 1. What was READ this lane (beyond RESEARCH section 1)

Two helpers read the binaries on the RE box (scratch `/var/tmp/c788/`, `/var/tmp/c788b/`).

- **RESEARCH section 1 is wrong about the message box.** 0x8613b0 is not a modal box: it writes a
  line into the title's window **500** (`GDR_TEXT_MESSAGE`, pstitle.txt Title, a CIFTextBox, FontColor
  255,255,103,29, HAlign 0), plays `snd_error`, and restarts timer 1000 at **15 000 ms**, which
  clears it (0x860c60). A new message replaces the last; no title, no button. Placed by 0x866760
  (0x86695e..0x8669b1, read this lane) at window 2's top-left + (9, 0x18), the screen's width x 0x49.
  Without window 500 a Win32 `MessageBoxW` "NetError" stands in.
- **Connect** (0x869460 -> 0x8688f0): a press with the lock (+0x144) above 0 is ignored silently;
  empty ID / password / no matching shard: nothing, no message, no lock; otherwise CITATION on the
  line, `0x862410(1)` (the title's input off, `CGWnd+0x62 = 0`), 0x6102, lock = 3.0 s even if the send
  failed. The lock counts down every frame unconditionally (0x8692b5). **Any 0xA102** turns the input
  back on (0x86c08c); after a success it stays off until select.
- **No "(C<n>)" for a failed gateway connect**: the title never connects -- the version check does
  (CPSVersionCheck::OnCreate 0x86d370), and a failure there is a Win32 box and quit. The agent's
  failed connect is "(C9)" (0x4cf500 posts 9; 0x86c5e5).
- **The drop box** (slot 40, 0x862450; title, select, create, quick start): CIFMessageBox, MsgBoxINIF,
  308 x 148 at (W/2 - 150, H/2 - 72), `UIIT_STT_CONFIRM_BOX` / `UIIT_MSG_MSGBOX_NETOFF`, only button
  202 (`UIIT_CTL_CONFIRM`); Confirm (0x641eb0) -> CPSQuit: **the client quits**. The world
  (CPSMission::vslot_040 0x84ae90) shows the same box and quits too.
- **The '#' rule** (0x86c136..0x86c416): only a reason ending in '#' is split (0x864790 is an
  ends-with test); "[Block Detail]" is a CIFButton id 800, 15 s, opening the address in
  `IEXPLORE.EXE` (0x865cc0); the cut uses a byte offset of a wide string (a retail bug).
- **The date** (0x4cf350): `GetDateFormatA(LOCALE_USER_DEFAULT, LOCALE_USE_CP_ACP, st, the user's
  LOCALE_SLONGDATE)` + " " + `GetTimeFormatA(.., LOCALE_STIMEFORMAT)`; the u32 fraction dropped.
- **The image (IBUV)**: GatewayServer makes it itself (IBUV module 0x419xxx -> ImageTrans.dll
  `fnImageTransToMemW`, 200 x 64, 0x800 buffer). Blob = u16 compressed length, u16 output size
  ((H+1)*W), u16 W, u16 H, a **zlib** stream (compress2 level 9; client zlib 1.1.4 `uncompress`
  0x4d8e00). **1 bit a pixel**, LSB first, rows top-down, set = white (0x62c500); drawn unscaled. The
  real 0x2322 handler is 0x4d01e0 (0x4cd3c0 is its reader). The window (0x2f, CIFConfirmbox,
  ifconfirmbox.txt): no Cancel; Enter submits once per picture (latch +0x380), the button always; the
  text as typed; every 0xA323 hides it; the gateway clears the code before comparing (0x406ab0).
- **Encryption**: 0x6323 **plain** (allocator 0, 0x4c96ab); 0x7007 **plain** (the generic sender
  0x841590 encrypts only 0x704C); 0x2002 plain; 0x6102 / 0x6103 encrypted. Gateway: 0x2322 and 0xA323
  plain; 0xA102 refusals mixed.
- **Keep-alive** (0x4cf990): an empty 0x2002 when nothing was sent for 5000 ms, checked every
  1666 ms, on the gateway and the agent from the server's 0x2001 on.
- **0x6103's six bytes**: the MAC of the Ethernet adapter holding the local address
  (`CNetEngine::vslot_034` 0x4a1950, GetAdaptersInfo), zeros when none; AgentServer stores and does
  not check them (0x402390).
- **After 0xA103 [1]**: nothing more from the net layer; select's OnCreate sends only 0x7007 [2].

## 2. What was built

- `client/scripts/net/login_ack.gd` (`LoginAckNet`): 0x6102 encode/decode, 0xA102 encode/decode, the
  twin of `session/loginack.go`; `login_ack_test.gd` plays every vector of `login_golden.json`.
- `client/scripts/frontend/login_messages.gd` (`LoginMessages`): every 0xA102, 0xA103 and 0xA323
  text, the "(C<n>)" suffix, the punishment box, the date, the '#' cut, NETOFF; textuisystem via
  `UiTextTable`, our own short English without Media.pk2.
- `Login.gd`: Connect sends 0x6102 (`NetClient.gateway_login`) instead of OpLogin; the READ checks,
  lock, input off while answered (a full-screen catcher), window 500 at its READ place and colour with
  `snd_error` and the 15 s clear; the drop box; the legacy path. The register link (OURS) unchanged.
- `NetOffBox` (MsgBoxINIF from ifmessagebox.txt): on the title, CharacterSelect and CharacterCreate;
  Confirm quits.
- Legacy: `RetailGatewayClient` past the list (login, image code, agent, lobby states; events);
  `RetailCaptcha` (the blob); `RetailLink` (socket, retries, keep-alive); `RetailLogin` (gateway ->
  agent); `CaptchaWindow` (ifconfirmbox.txt); `NetClient.attach_retail` -- the adapter: while
  attached, `_send` carries only 0x7007 on the agent in the original framing and the agent's frames
  go through `_dispatch` (0xB007 -> `character_list_result` as before). CharacterSelect: Start on a
  legacy agent shows an OURS line and sends nothing; the drop box replaces the old line + return.
  `ServerListWindow.chosen_shard_name` (the chosen row's shard).
- Go (`server/internal/retailgw`): `login_client.go` (the Conversation's login states, `RunLogin`),
  `fake_login.go` (`Config.Login`: 0x6102, IBUV with a real zlib picture, 0xA102, the agent's 0x6103 /
  0xA103, the list), `Config.Deadline`; hooks in `client.go` and `server.go` are a few lines each.
  `cmd/retailgw serve -login user:pass -captcha c -agent-listen a` and `retailgw login`.
- NetClient judges the character list's 5 s timeout after the frame's reads (the live run's select
  reported "no answer" for a list the server answers in under 10 ms: the harbour build blocked the
  first frame longer than 5 s, and the timeout was checked before the socket was read).

## 3. OURS choices

- Content id to OpenSRO's server: the archive's (DIVISIONINFO.TXT via RetailClientInfo), else 0;
  shard id 0. Success's empty agent host / port 0 = stay on this connection (the base's).
- A failed connect (OpenSRO's server or a legacy gateway): `UIO_MSG_ERROR_SEVER_CONNECT`, no suffix.
- The date: Windows' en-US defaults, "Thursday, October 22, 2026 1:05:09 PM", whatever the locale.
- The '#' cut where the code means it; no "[Block Detail]" button.
- The image window centred; PML reduced to plain lines; edit max 0x200 (CIFEdit's default, INFERRED).
- 0x6103's trailer: six zeros (Godot cannot read a MAC; retail sends zeros itself when none matches).
- The legacy shard: the chosen list row's shard name (remembered), else the server's name, else the
  list's only shard. The config's `agent:` entry stands in for 0xA102's address (proxies, tests).
- The input-off state is a full-screen input catcher; the fields let go of focus.
- World3D still returns to the title on a drop (QA reconnect relies on it): docs/TODO.md.
- QA only: `OPENSRO_QA_LEGACY_LOGIN=id:pw`, `OPENSRO_QA_CAPTCHA=code`.
