# Round 789, lane K: `.pk3` asset packs in the client and the native library

Round 789 is "asset packs (.pk3) and working avatars". The user (2026-10-16): "Let's add support for
pk3 (zip) files and check what we have written down for that already." The spec is docs/TODO.md,
"Asset packs: `.pk3` beside `.pk2`" (decided 2026-10-01); lane G wrote the rules every reader
follows into docs/protocol/asset_packs.md and built the Go side and the converter. Lane K (this
note) built the client's side: one layered archive set under every client reader, the pack reader
in GDScript and Rust, the source mode, the "which layer served this" command, the tests and the
measurements. Branch `feat/pk3avatar789-k`.

Labels: **READ** (our own code), **MEASURED** (the render box 192.168.10.78, Godot 4.7.2,
`RENDER_DIR=/opt/opensro-client-789k`, the native library built from this branch unless said),
**OURS**, **OPEN**. Retail has only `.pk2`: everything about packs is OURS; nothing here was read
from a binary.

## 1. What was there (READ; /root/opensro-pk3av789/SURVEY_PK2.md)

13 runtime `Pk2Reader.open` sites in 9 files, each opening its own handles; every lookup through
`ObjectLoader.find_file`; 159 parameters typed `: Pk2Reader`; `custom/` held only round 678's
branding; caches keyed by the private `_file` (UI fonts) and `source_path` (the item and NPC
tables); AudioBank's own three handles. The survey is right on every point checked.

## 2. Built (OURS)

- **One set, opened once** (`client/scripts/assets/asset_archives.gd`, `AssetArchives`): the 13
  open sites now ask `AssetArchives.data()` / `map()` / `media()` / `music()` / `particles()`
  (World3D's five, Login, FrontEndUi, the select stage, CharacterCreate, the preview, the
  appearance's Particles fallback, AudioBank). Each base archive is opened the first time it is
  asked for and shared by every scene and thread. Boot logs the set at start.
- **Volumes and layers** (`layered_archive.gd`, `LayeredArchive extends Pk2Reader`): `custom/`,
  then the packs (later name first), then the volume's base layers (`Data.pk3` over `Data.pk2`
  when both are read). A view is a `Pk2Reader`, so the 159 typed parameters and every caller are
  unchanged. An Entry carries its layer (`_layer`, new on `Pk2Reader.Entry`); merged folders carry
  their key (`_path`) and list every layer's names. When nothing overlays a volume the caller gets
  the base archive's own handle, as before.
- **The lookup** became the archive's own method (`Pk2Reader.find_entry`): `ObjectLoader.find_file`
  asks the archive, so a `.pk2`, a `.pk3` and a view each answer their way; the GDScript walk is
  `Pk2Reader.walk_find` (the test stubs that override `read_dir` keep working through it).
  `Pk2Reader.open` opens a `.pk3`/`.zip` as a `Pk3Reader`.
- **The pack reader**: `client/scripts/pk2/pk3_reader.gd` (GDScript: central directory incl.
  zip64, a case-insensitive index, stored reads positional, deflated ones inflated by Godot's zlib
  through a synthesized gzip member whose trailer is the entry's CRC-32 and size) and
  `native/src/core/pk3.rs` + `SrNativePk3` (miniz_oxide into an exact-size buffer, crc32fast).
  Native interface 5 -> 6 (`core::API`, `NativeAssets.NATIVE_API`).
- **The source mode**: `setting/config.yaml` `assets.source` (`ClientConfig.asset_source`),
  `OPENSRO_ASSET_SOURCE`; `Pk2Config.source_mode()`, `volume_chain()`, `pack_dir()`
  (`OPENSRO_PACK_DIR`).
- **Which layer served this**: `/layer <path>` (Console), `OPENSRO_QA_WHICH`,
  `client/tools/which_layer.gd`, the Shift+F3 panel's archive lines.
- **Fixed dependencies** (the survey's list): the UI font cache and the item/NPC table caches key
  by `Pk2Reader.cache_key()` (the file, plus the set's generation for a view); AudioBank shares
  the set's handles, never closes them, and drops its handles and sounds when the set is reopened;
  the audio warm-up's `"prim\snd\<d>\ "` probe still decodes the base's folder (tested).
- **For lane U**: `AssetArchives.reopen()` (a new set; handles taken before keep the old one) and
  `AssetArchives.current_generation()`. Not `reload()`: on a `class_name` that resolves to
  GDScript's own `Script.reload` (MEASURED: "Cannot reload script while instances exist").
- **Tools**: `pack_bench.gd` (the load benchmark), `pk3_parity.gd` (a `.pk2` against its converted
  `.pk3`, both readers), `which_layer.gd`. `perf_gate.sh`: `--cold` drops `*.pk3`/`*.zip` (and
  `OPENSRO_PACK_DIR`'s packs) from the page cache too; an `--ab-env` that is not the native A/B
  keeps the library on both sides.

## 3. Lane G's rules (docs/protocol/asset_packs.md), matched

The coordinator relayed lane G's rules mid-round; the client was changed to match: volumes (rule 3:
a lookup names its base archive; Data and Map each have an object.ifo), the simple lower-case
mapping (pk2.rs's `lower` no longer uses Rust's full `to_lowercase`), lookups skipping empty
segments with `.`/`..`/`:` served by no layer (`Pk2Reader.clean_path`, `pk2::path_segments` -- the
native pk2 lookup too), the mode `pk2` reading extra `.pk2` packs, `custom/` read in every mode
with its symlinks refused, `.zip` as a base, the ratio cap 1100:1 per entry (over 64 bytes) and per
pack (my first cut used deflate's 1032:1 plus slack and no pack-wide check). Where the client
differs, on purpose (OURS; asset_packs.md "Client"): `custom/` is round 678's folder beside `pk2/`,
not `<archives>/custom`; a pack entry whose data would lie past the file's end is refused at open;
a symlink entry in a pack is refused (lane G's Go `checkZipEntry` does not look at an entry's mode
-- for the coordinator).

`pack_bench.gd` (20,000 Data paths, fresh handles each round, medians of 5, ms):

| | native: open / view / find / read / total | GDScript: total (find) |
|---|---|---|
| Data.pk2, plain `Pk2Reader` | 1.1 / 0 / 99 / 266 / 367 | 9,264 (9,089) |
| Data.pk2, empty pack folder | 0.1 / 1.0 / 100 / 264 / 365 | 9,256 (9,079) |
| Data.pk2 + a pack overriding 6 Data files | 0.3 / 1.6 / 138 / 275 / 415 | 9,311 (9,062) |
| Data.pk3 (converted), plain | 89 / 0 / 79 / 2,661 / 2,830 | 4,060 (72; open 491) |

So an empty pack folder costs nothing; a pack costs ~2 us a lookup natively (the view's
lower-casing and index probe); a converted Data.pk3 trades the Blowfish directory (GDScript
lookups ~120x cheaper) for the inflate of every read (`.ddj` is deflated in lane G's packs: native
reads ~10x dearer). The world entry measured SAME either way. Reading all of Data.pk3 (3.66 GB):
8.5 s native, 11.0 s GDScript; the native read was 15.1 s with a byte-at-a-time CRC-32 table,
hence `crc32fast`. Opening Data.pk3 (75,872 entries, zip64): 104 ms native, 543 ms GDScript.

## 5. OPEN

- The server naming the packs a client needs, with their hashes, and the updater fetching them
  (lane U); the client side is `AssetArchives.reopen()`.
- A volume-scoped pack (asset_packs.md rule 3).
- The Windows library: cross-built with the new crates (`cargo build --release --locked --target
  x86_64-pc-windows-gnu`, finished), never run on Windows (as before, native/README.md).
- The GDScript reader's inflate goes through a whole-entry gzip buffer copy; no streaming or ranged
  read exists anywhere in the client, so none was added.
- A `.pk3` whose `.ddj` is stored (`pk2topk3 -store .ddj`) would read without inflating; not
  measured here.
