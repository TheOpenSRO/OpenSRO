# OpenSRO server

The Go game server for OpenSRO: a clean-room reimplementation of a Silkroad
Online–style server, written from what was recovered out of the original
binaries and the player's own client archives. It ships **no game data**: every
table it needs is generated by the operator from their own client (see
[Reference data](#reference-data)).

This file is guarded by a test (`internal/systems/readme_test.go`): every tool
under `cmd/` and every flag `cmd/server` registers must be mentioned here, or
`go test ./...` fails. When you add one, add it here in the same change.

## Build and run

```
go build ./... && go test -p 1 ./...                 # the real loop
go run ./cmd/server -in-memory -addr 127.0.0.1:15899 # no database, nothing persisted
go run ./cmd/server -postgres-dsn 'postgres://postgres:postgres@localhost:5432/opensro?sslmode=disable'
```

The production shape is the compose stack in the repo root (`docker-compose.yml`,
`deploy/`): Postgres plus the server, the server rebuilt from `origin/dev` by
`deploy/update.sh`. The public test server and its exact override are described
in `deploy/README.md` and `docs/HANDOFF_OPENSRO.md`.

## `cmd/server` flags

| flag | env default | what |
|---|---|---|
| `-addr` | — | listen address for the gateway (`:15779`) |
| `-postgres-dsn` | — | PostgreSQL DSN; the persisted store for accounts, characters, inventory, equipment, storage, guilds, friends, quests, skills, reference items/skills/drops |
| `-postgres-wait` | `60s` | how long to wait at startup for PostgreSQL to accept connections, retrying every second (`0`: one try). At a host's boot Docker starts the server and postgres together, ignoring compose's `depends_on`, so postgres may not be up yet (deploy/README.md) |
| `-in-memory` | — | run with in-memory stores instead of PostgreSQL (QA renders, tests, local play; nothing survives a restart) |
| `-tls-cert` / `-tls-key` | — | serve TLS on the gateway instead of plain TCP |

## Reference data

The server reads no game text tables directly. The operator generates CSVs from
their own `Media.pk2` and either passes them on the command line (in-memory) or
imports them into PostgreSQL:

- `cmd/export-refdata` — itemdata / skilldata / characterdata text tables → `items.csv`, `skills.csv`, `monsters.csv`
  (read in the client's **index order**, not glob order: ids collide across parts);
  `-mode npcpos` → `npcpos.csv`; `-mode teleport -out <dir>` → the three teleport CSVs.
- `cmd/export-leveldata` — `leveldata.txt` → `leveldata.csv` (the EXP curve).
- `cmd/import-refdata` — loads items, skills and, when an operator has them, the
  drop tables (`-drops-csv`, `-drop-groups-csv`) into PostgreSQL. The drop tables
  live only in the original shard database and are absent from every client
  archive; until an operator supplies them, loot content is a disclosed placeholder.

The full recipe, as actually run on the public server, is `deploy/README.md`.

## Layout

`internal/` is one package per system; the ones that carry recovered rules cite
their source in the code (`combat`, `durability`, `berserk`, `leveldata`,
`skillparam`, `character`, `equipment`, `grounditem`, `repair`, `rates`,
`storage` -- the warehouse is the account's, with a one-time boot migration
from the older per-character table).
`session` holds the wire handlers (our own protocol; opcodes and payloads are
documented next to the handlers and in `docs/protocol/`), `gateway` the TCP
layer, `world` the zone hub, `persistence` the recovered model of the original
database, and `systems` the test that keeps `docs/SYSTEMS.md` honest.

## Tests

`go test -p 1 ./...` from this directory. Twelve packages' tests use a local
PostgreSQL test database (`OPENSRO_TEST_POSTGRES_DSN`, default
`postgres://postgres:postgres@localhost:5432/opensro_test?sslmode=disable`);
`internal/testdb` serialises test *processes* on it with an advisory file lock,
so parallel suite runs from several checkouts no longer clobber each other's
rows (two runs both pass; the second waits). The `systems` and `refdata`
packages guard the documentation: `docs/SYSTEMS.md`'s rows, this README, and
`docs/protocol/recovered_names.tsv`.
