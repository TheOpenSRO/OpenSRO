# srrevamp server

The Go game server for srrevamp: a clean-room reimplementation of a Silkroad
Online–style server, written from what was recovered out of the original
binaries and the player's own client archives. It ships **no game data**: every
table it needs is generated by the operator from their own client (see
[Reference data](#reference-data)).

This file is guarded by a test (`internal/systems/readme_test.go`): every tool
under `cmd/` and every flag `cmd/server` registers must be mentioned here, or
`go test ./...` fails. When you add one, add it here in the same change.

## Build and run

```
go build ./... && go test -p 1 ./...                 # the real loop
go run ./cmd/server -in-memory -addr 127.0.0.1:15899 # no database, nothing persisted
go run ./cmd/server -postgres-dsn 'postgres://postgres:postgres@localhost:5432/srrevamp?sslmode=disable'
```

The production shape is the compose stack in the repo root (`docker-compose.yml`,
`deploy/`): Postgres plus the server, the server rebuilt from `origin/dev` by
`deploy/update.sh`. The public test server and its exact override are described
in `deploy/README.md` and `docs/HANDOFF_OPENSRO.md`.

## `cmd/server` flags

| flag | env default | what |
|---|---|---|
| `-addr` | — | listen address for the gateway (`:15779`) |
| `-postgres-dsn` | — | PostgreSQL DSN; the persisted store for accounts, characters, inventory, equipment, storage, guilds, friends, quests, skills, reference items/skills/drops |
| `-in-memory` | — | run with in-memory stores instead of PostgreSQL (QA renders, tests, local play; nothing survives a restart) |
| `-tls-cert` / `-tls-key` | — | serve TLS on the gateway instead of plain TCP |
| `-leveldata-csv` | `SRREVAMP_LEVELDATA_CSV` | the EXP curve (`export-leveldata`); **without it characters never level** |
| `-skills-csv` | `SRREVAMP_SKILLS_CSV` | skill reference data (`export-refdata`), in-memory mode; PostgreSQL imports it instead |
| `-items-csv` | `SRREVAMP_ITEMS_CSV` | item reference data (`export-refdata`), in-memory mode; PostgreSQL imports it instead |
| `-npcpos-csv` | `SRREVAMP_NPCPOS_CSV` | the game's monster placements (`export-refdata -mode npcpos` on a client's `npcpos.txt`); every roster species with rows stands where the game puts it, otherwise at its own-design anchor near the town |
| `-gm-accounts` | `SRREVAMP_GM_ACCOUNTS` | comma-separated account usernames allowed to run the in-game GM commands (`/tp`, `/give`, `/level`, ...); case as stored in `accounts.username`; default none. Every command is logged with the account. See `docs/DEBUG_TOOLS.md` |
| `-monster-ai` | `SRREVAMP_MONSTER_AI` | **default off**, and the kill switch. On, the monster AI tick runs: monsters idle, wander at their walk speed, run home past a 200-unit roam radius (own design), and stand where a blow found them while the attacker's auto-attack runs, each move pushed to the zone (`OpMonsterMoved`). Off, nothing moves and the wire is what it was. The env value is `strconv.ParseBool`'s (`1`, `true`, ...); anything else is off with a WARN. Needs a client of v0.1.435 or later. The boot log says which (`monster AI on: ...` / `monster AI off ...`). See `deploy/README.md`, "Monster AI (off by default)" |

At boot the server logs what reference data its database holds
(`reference data in PostgreSQL items= skills= monsterDrops= dropGroupEntries=`)
and **warns when it has no items** — that state is what made every hit deal 1
and no kill pay EXP on the public server until 2026-09-19. Env-only settings
are the QA accelerants, which are never for real play
(`SRREVAMP_DURABILITY_LOSS_ALWAYS`), and the monster AI's trace
(`SRREVAMP_AI_TRACE`: every state change, leg, strike and release, and a keep-up
that ends out of reach -- several lines a second in Jangan, so only for a check). The GM console's account list is the
`-gm-accounts` flag above (env `SRREVAMP_GM_ACCOUNTS`); the commands a tester
and a GM get are in `docs/DEBUG_TOOLS.md`.

## Reference data

The server reads no game text tables directly. The operator generates CSVs from
their own `Media.pk2` and either passes them on the command line (in-memory) or
imports them into PostgreSQL:

- `cmd/export-refdata` — itemdata / skilldata text tables → `items.csv`, `skills.csv`
  (read in the client's **index order**, not glob order: ids collide across parts).
- `cmd/export-leveldata` — `leveldata.txt` → `leveldata.csv` (the EXP curve).
- `cmd/import-refdata` — loads items, skills and, when an operator has them, the
  drop tables (`-drops-csv`, `-drop-groups-csv`) into PostgreSQL. The drop tables
  live only in the original shard database and are absent from every client
  archive; until an operator supplies them, loot content is a disclosed placeholder.

The full recipe, as actually run on the public server, is `deploy/README.md`.

## Tools under `cmd/`

| tool | what |
|---|---|
| `server` | the game server |
| `export-refdata` | itemdata/skilldata → CSV from the player's own archive |
| `export-leveldata` | leveldata → CSV (the EXP curve) |
| `import-refdata` | CSVs → PostgreSQL reference tables |
| `pk2list` | list paths inside a pk2 archive; `-extract` one file |
| `heightat` | the raw terrain height a real `.m` heightmap gives at a spot |
| `wherecoord` | convert the position the real client displays to region/local/world coordinates |
| `whatishere` | the real objects placed near one spot in one region |
| `findregionassets` | scan every region's `.o`/`.o2` placements for an asset |
| `scanlandmarks` | scan placements for landmark objects (world map work) |
| `o2sectors` | check a `.o2` file's entries against its sector grid |
| `auditcharacters` | walk the real character/equipment asset chain and report what resolves |
| `audittextures` | walk the whole object catalog and report texture resolution |

## Layout

`internal/` is one package per system; the ones that carry recovered rules cite
their source in the code (`combat`, `durability`, `berserk`, `leveldata`,
`skillparam`, `character`, `equipment`, `grounditem`, `repair`, `rates`,
`storage` -- the warehouse is the account's, with a one-time boot migration
from the older per-character table).
`session` holds the wire handlers (our own protocol; opcodes and payloads are
documented next to the handlers and in `docs/protocol/`), `gateway` the TCP
layer, `world` the zone hub, `persistence` the recovered model of the original
database, and `systems` the test that keeps `docs/SYSTEMS.md` honest.

## Tests

`go test -p 1 ./...` from this directory. Twelve packages' tests use a local
PostgreSQL test database (`SRREVAMP_TEST_POSTGRES_DSN`, default
`postgres://postgres:postgres@localhost:5432/srrevamp_test?sslmode=disable`);
`internal/testdb` serialises test *processes* on it with an advisory file lock,
so parallel suite runs from several checkouts no longer clobber each other's
rows (two runs both pass; the second waits). The `systems` and `refdata`
packages guard the documentation: `docs/SYSTEMS.md`'s rows, this README, and
`docs/protocol/recovered_names.tsv`.

## Where the truth lives

- `docs/SYSTEMS.md` — which systems are specified, partial or open, each with its next probe.
- `docs/protocol/` — the recovered file formats and per-system specs with their citations.
- `docs/WORLD_ISSUES.md` — the numbered rounds: every non-obvious finding with its evidence.
